# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [0.2.0] - Unreleased

Work in progress on branch `feature/v0.2.0`: real screenshot analysis, multi-screen journeys, evidence-region mapping, HTML reports with annotations, and a measured evaluation framework. v0.1.0 behaviour is preserved and protected by the checks below.

### Added (Phase 4: journey and information-architecture checks)
- New optional 0.2.0-only fields `input_context.screens[].heading` and `.navigation[]` (`label`, `level`, `selected`, `destination`), added to the version gate (now 7 gated fields).
- `scripts/lib/journey.mjs`: transitions must reference real journey screens, follow step order, cover every consecutive step pair and not repeat; `journey` and `transition` findings need a journey and evidence from two or more screens. Orphan screens warn.
- `scripts/lib/ia.mjs`: one label leading to two screens, unknown destinations, multiple selected items per level and a selected item leading elsewhere are errors. Missing selection, label and heading mismatch, multiple labels for one screen and unreachable screens are warnings.
- `references/journey-analysis.md`, linked from SKILL.md and the journey workflow.
- Tests: `journey.test.mjs`, `ia.test.mjs`, plus updated gate tests. All checks apply to 0.2.0 reviews only; 0.1.0 reviews are never journey- or IA-checked.

### Added (Phase 3: review-level image checks)
- `scripts/lib/imagerefs.mjs`, wired into `validateAll` (new optional `{ baseDir }` argument; `validate-review.mjs` passes the review's folder). Applies to `schema_version` 0.2.0 only.
- Checks: extension vs format, aspect ratio vs screen, evidence box bounds, evidence-to-annotation links, and, with a folder, file existence, validity, containment, SHA-256, format and pixel size.
- 14 tests (`imagerefs.test.mjs`), with a mutation for each failure and a guard that 0.1.0 reviews are never image-checked.

### Added (Phase 2: schema extension and version gating)
- `review.schema.json` accepts `schema_version` `0.1.0` or `0.2.0`. New optional fields: `input_context.screens[].image`, `input_context.journey.transitions[]`, `findings[].scope`, `findings[].evidence[].bbox` and `.annotation_id`.
- `scripts/lib/version.mjs`: the version gate. A `0.1.0` review using any 0.2.0-only field is rejected; unknown versions are rejected. Wired into `schemaErrors`, so every existing script uses it.
- `references/schema-versions.md`: rules, field table, step-by-step migration example and the known limitations (image metadata, JPEG decoding) to resolve before the public release.
- 23 tests (`version.test.mjs`, `version-strict.test.mjs`): positive and negative compatibility, strict typing of every new field, migration path.
- v0.1.0 example reviews, reports, eval cases and scoring are unchanged.

### Added (Phase 1: image ingestion)
- `scripts/lib/image.mjs`, `png.mjs`, `jpeg.mjs`: content-signature detection, structural validation (PNG CRCs and bounded inflate, JPEG segments), size limits, SHA-256. No new dependencies.
- `schemas/manifest.schema.json`, `scripts/lib/manifest.mjs`, `scripts/ingest-screens.mjs` (`npm run ingest`, `npm run verify:fixtures`): strict manifest, build and verify.
- `references/screenshot-ingestion.md`; synthetic fixture `evaluations/fixtures/ingest-basic/` generated by the dev-only `tools/fixtures/generate.py` (Pillow, not used in CI).
- 22 tests for signatures, extension mismatches, oversized, truncated and corrupted files, and the manifest.

### Changed
- The `0.1.0` heading no longer says "Unreleased": it was released as tag `v0.1.0` (the tag is unchanged).

### Added (Phase 0: baseline and backward-compatibility guard)
- `scripts/tests/compat-v01.test.mjs`: pins the v0.1.0 example files, eval case files, scoring constants and example scores by hash and value; checks that v0.1.0 reviews validate and render byte-identically.
- `scripts/check-compat.mjs` and `npm run compat`: runs the tests, examples and eval cases exactly as released at tag `v0.1.0` against the current code, in a temporary copy.
- CI: the workflow also runs on `feature/**` branches, fetches full history and tags, and runs the compatibility check.
- Git tag `v0.1.0` on commit `5b21937`.

## [0.1.0] - 2026-11-22

### Added
- Agent Skills-format skill `design-critic` under `.cline/skills/design-critic/`.
- Eight review dimensions: usability, information architecture, visual hierarchy, interaction design, accessibility, content design, design system consistency, product alignment.
- Detailed methodology references, six workflows, and a versioned JSON output contract (JSON Schema 2020-12).
- Deterministic scoring (formula v1.0) with severity, confidence and reach weighting.
- Node.js tooling (Ajv): review validation, score computation, annotation checks, Markdown report rendering, skill linting.
- Five worked examples (fintech, e-commerce, SaaS, mobile, and a four-screen healthcare portal focused on information architecture).
- Dimension synchronisation tests: the eight dimensions in `common.schema.json`, `scoring.mjs`, the schemas, the examples and the reference guides must agree.
- Evaluation suite with positive, negative (anti-hallucination) and mutation-based meta cases.
- GitHub Actions workflow for automated validation.
